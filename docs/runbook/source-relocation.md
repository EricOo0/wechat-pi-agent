# TypeScript 源码目录迁移检查

适用：R-001，Node ESM 项目。依据：本次 96 个源文件迁移与 [完整检查](../specs/system-refactor/evidence/README.md)。

## 相对路径分三种处理

- import/export 和动态 import 相对于源文件。移动文件后重算路径；源码的 `.ts` 对应导入中的 `.js`。
- `.env`、`./data` 等传给文件 API 的相对路径通常相对于进程 cwd。不能跟着源码位置一并改写，否则配置和用户数据会读错位置。
- `new URL(path, import.meta.url)` 相对于模块文件。沙箱 worker、提示词等构建资源需同时检查源码和 dist 路径。

本次最初按所有“点开头字符串”重算路径，会错误改变 CLI 的 `.env`/数据默认值。已改为仅依据真实模块目标重写导入，再单独核对资源路径。不要只靠类型检查判断路径迁移正确。

## 验证步骤

1. 先跑基线并保存结果，记录原路径映射。
2. 迁移 import/export、测试及构建脚本；保持运行数据路径和主体 ID。
3. 执行 `npm run check`，包含模块依赖检查、测试和实际构建。
4. 检查构建复制出的提示词、supervisor 和 tool-worker；使用隔离 Dry Run / 退出集成测试，不重启用户真实服务验证路径。
5. 修复文档链接；旧历史材料中的代码版本说明与当前入口分别标注。

成功信号：没有旧模块导入，类型与构建通过，消息/权限/文件/退出回归通过，用户数据路径未变。失败时先区分模块解析、cwd 相对路径和构建资源缺失，避免创建旧目录转发层掩盖遗漏。
