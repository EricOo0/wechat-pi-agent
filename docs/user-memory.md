# 用户记忆与 Session 生命周期

本功能使用已有 Pi 模型认证，以用户为单位保存 Markdown 记忆。没有 embedding，没有新的模型 API Key 配置，也不在正常聊天过程中让模型直接编辑记忆文件。

## 存储

```text
data/memory/<subjectKey>/
├── MEMORY.md
└── sessions/YYYY-MM-DD/<sessionId>.md
```

subjectKey 与用户文件库一致，由用户身份、执行环境和工作区共同确定。日期在结束 Session 时按服务所在时区确定，并作为任务的固定 detailId 保存。

Markdown 是记忆正文的事实源。SQLite 的 `memory_jobs` 保存阶段、租约、重试状态和来源，`memory_job_events` 保存后台 Trace。文件以临时文件 + rename 原子替换，目录 0700、文件 0600。总览最多 6000 字符（模型输出预算 5500），明细最多 60000 字符。用户手动编辑也须遵守读取限制和路径约束。

## 结束时机

- `/new`：结束旧 Session。命令后已经排队的普通消息改属新 Session；旧会话的授权续跑取消。
- 闲置：每分钟扫描；无 QUEUED/RUNNING Turn，且最后一条消息入库或 Turn 完成已超过 1 小时才结束。判断与归档在事务内完成，收到新消息会阻止误归档。
- 正常退出：先停止拉取与领取任务，给正在执行的任务最多 30 秒收尾时间；超过后发出取消，待调用取消收尾后再关闭资源。归档剩余 Session 并入队记忆任务，不在退出时启动总结请求。
- 启动恢复：在持有数据目录单实例锁并成功绑定 Admin 端口后，归档上个运行留下的 ACTIVE Session；未完成 Turn 标记中断取消，不自动重复执行其工具。已生成的 Outbox 回复继续走发送恢复。

`main.ts` 使用 proper-lockfile 锁定数据目录，10 秒更新、30 秒过期。启动前还会检查 Admin 端口，避免未退出的旧版本被迁移影响。正常退出释放锁；硬崩溃无法执行 finally，重启可能需要等待旧锁过期。锁丢失会立即取消工作，旧实例不再归档会话。嵌入式调用 `buildApp` 的宿主也必须遵循同样的单实例约束。

归档 Session 与创建记忆任务在 app.db 同一事务完成。权限数据在独立 permissions.db，撤销采用幂等补偿；未完成清理的 Session 不进入记忆生成，后续扫描/启动重试。

## 后台写入

任务阶段：PENDING → EXTRACTED → COMPLETED；仅管理命令等没有可整理内容的 Session 为 SKIPPED。

1. 从已封闭会话读取用户消息、已生成回复、文件元信息和有限的工具证据。
2. `PiMemoryGenerator.extract` 返回会话 Markdown 与是否需要更新总览。
3. 发布明细、保存 EXTRACTED 检查点。
4. 有长期价值时读取当前总览与明细，调用 merge，原子发布总览。

单个后台 worker 领取任务，同一用户按顺序整理；租约 60 秒，每 10 秒续期。发布和检查点写入在同一数据库写锁范围内执行，失去租约不得发布。失败指数退避，最长 1 小时；EXTRACTED 后失败不会重新提炼。Markdown 中的任务标记用于识别文件已经发布但数据库检查点尚未完成的崩溃窗口，避免重复合并。

模型调用没有业务工具，只返回受校验的 JSON。只将可复用事实、明确偏好、决定及未完成业务事项提升到总览；不把助手建议当作用户决定，不保存凭据、授权状态、签名链接、文件全文或加密推理。源消息的 REPLY_PENDING 只代表发送排队，不代表助手还没有生成回复。

输入最多取最近 300 个 Turn；每条用户文字最多 8000 字符、助手回复最多 12000 字符，最多 10 条工具证据、每条 4000 字符预览。总输入超过 160000 字符时丢弃较早轮次并标记截断。该范围不是完整历史承诺，可在记忆任务 Trace 中审计输入。

## 读取

每个 AgentSession 创建时读取一次总览，并在 Pi Session 中保存快照及 revision。后台更新不会改变已开始会话的总览；新 Session 读取当时的最新版本。总览读取失败时记录失败 Trace，并以空记忆开始，不阻断普通聊天。恢复和压缩继续使用原快照，不重新读新版。

- `memory_search(query, limit?)`：字面关键词搜索；默认最多 20 个命中、上限 50；扫描总览及最新 1000 个明细文件，返回 memoryId、行号、片段和截断提示。
- `memory_read(memoryId, startLine?, lineCount?)`：读取命中明细；1-based 行号，最多 200 行。

工具只访问当前用户目录。受限模式下普通 read/bash 不因记忆功能而获得目录权限。总览是历史背景，不赋予权限；当前用户纠正优先。搜索读取可以看到后来更新的文件，但不会自动替换当前会话的总览快照。

## Trace 与验收

Admin 页“记忆任务”按钮切换后台任务视图。可查看提炼、合并的模型输入输出，以及 `memory_detail`、`memory_overview` 的发布内容与版本变化。聊天 Trace 中 `memory_load` 显示本次会话加载的版本。

接口：`GET /debug/memory/jobs`、`GET /debug/memory/jobs/:jobId`。

离线验证：`npm run check`。可选真实模型验证：构建后运行 `node scripts/verify-memory.mjs --live`，仅用隔离临时目录与合成偏好，验证结束会话 → 提炼 → 合并 → 新会话回答。结果写入 `docs/memory-verification.json`；不会读取真实聊天或修改全局 Codex 记忆。

直接修改明细不会自动重建总览；手动维护时需同时考虑总览。合并期间总览被修改会触发版本冲突重试，不覆盖新修改。

首版没有聊天内直接编辑/删除记忆的工具，也不自动清理历史明细。远端调用成本使用当前模型额度；已有会话结束后每次通常有一次提炼、至多一次合并。
