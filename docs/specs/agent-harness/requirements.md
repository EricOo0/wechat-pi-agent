# H-001：Agent Harness

本文为需求草案。用户已确认先完成系统架构重构，再扩展 Harness；候选条目不等于首期范围已全部批准。[开发状态与下一动作](../../changelog/planned.md#h-001-agent-harness)

## 问题与目标

当前项目已具备微信接入、Pi 运行时、受控工具和持久化。下一步希望明确会话与任务运行控制边界，并支持需要多次运行才能完成的目标。一次运行结束，不应直接等于用户目标完成。

## 候选需求与验收场景

| ID | 用户需求 | 候选验收条件 |
|---|---|---|
| H-001-1 | 同一会话有序提交和控制任务 | 连续输入不会产生两个同时修改同一会话状态的运行所有者；取消有明确终态 |
| H-001-2 | 长程任务保留目标与进展 | 单次 Run 结束但验收未满足时，保留目标、进展、停止原因及继续或等待的依据 |
| H-001-3 | 查看并控制目标 | 可查看进展、证据、阻塞原因；暂停、恢复、取消有可观察状态 |
| H-001-4 | 中断恢复不盲目重复副作用 | 恢复时核对已完成动作，无法判定是否执行的动作进入待确认状态 |
| H-001-5 | 满足条件才报告完成 | 按任务定义检查完成证据，失败或无法确认不会标记完成 |
| H-001-6 | 渠道通过稳定接口使用运行能力 | 微信协议与运行控制通过明确输入、事件和控制接口交互 |

## 约束与候选扩展

- 保留当前微信接收、发送、文件、记忆、模型管理和权限能力；实施计划确定回归场景。
- 长程执行不扩大授权；目标工作状态与用户长期记忆分别管理。
- Web / CLI、多会话并发、远端执行环境是扩展候选，不默认纳入首期。
