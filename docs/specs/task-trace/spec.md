# Task 维度 Trace 整合

用户已确认设计并授权实施，本地实现和验证已完成。[核对](reviews/local.md) · [证据](evidence/README.md)。H-001 是前置本地实现，H-002 扩展其可观测性，不改变任务执行协议。

## 范围与行为

以 Conversation → Task → 输入/Run/Review/控制/投递组织统一页面，复用原模型、工具和上下文 Trace。左侧按会话分组筛选任务；中部概览与时间线；右侧详情。正常旧 Run 默认折叠，最新及异常节点易于展开。

只实际执行 Agent 的请求标 Run；管理命令不伪装执行。保留初始目标、有序输入、版本及 replyTo，标记过期结果未推进任务。Review 为独立节点，明确完成申请、所属 Turn、判断与证据。预算来自 Task 实际计数，执行/Review 的 Token 和调用耗时分别累计；数据缺失显示不完整。

任务完成与 Outbox 送达分别展示；内部进展标记未发送。聚合查询仅关联现有数据，必要时补充持久化 Outcome 与运行上下文事件；不从最终状态倒推历史事实。保留旧 Trace/记忆入口及缺少 Task 的历史记录。

## 验收

| ID | 条件 |
|---|---|
| H-002-1 | 可信 owner 下聚合 Task、输入、事件、运行和 Outbox；不可查询其他用户 Task |
| H-002-2 | 统一三栏页面支持 Task/关键词/状态筛选及 Conversation 分组，空态、错误和历史入口可用 |
| H-002-3 | Run 保留模型工具树、请求响应/原始事件；Review 独立，关联完成申请和版本，保存结构化 Outcome |
| H-002-4 | 输入、控制、状态转换、过期结果与预算可追溯，不把管理请求计为 Run |
| H-002-5 | 执行和 Review 用量分开，缺失不冒充零；完成与投递独立，内部结果明确未发送 |
| H-002-6 | 原 Trace 查询/历史数据兼容；必要本地回归及页面交互验证通过，不声明部署 |

## 阅读体验补充

开始执行合并进对应 Run，申请完成与核对结论合并进 Review；无法可靠关联的历史事件保留紧凑条目，不丢弃原始记录。右侧 JSON 按对象/数组折叠，支持全部展开/折叠、10–24px 字体缩放、拖动高度及弹窗放大，Esc 关闭后保留阅读状态。对应 H-002-2/3/4。
